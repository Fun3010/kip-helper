# План проверки КИП Helper

Документ описывает проверки и условия приёмки, а не подтверждает успешные тесты, сборку или установку APK. Фактические результаты фиксируются отдельно с версией Flutter, моделью устройства, Android API и командой запуска.

## Автоматические проверки

| Область | Сценарии | Где |
|---|---|---|
| Ввод | Пробелы, запятая, минус, экспонента, пустое значение, NaN/Infinity | `test/domain_test.dart` |
| Температура | Опорные точки, все пары единиц, абсолютный ноль | `test/domain_test.dart` |
| Давление | Опорные коэффициенты, все пары, отрицательное избыточное давление, переполнение | `test/domain_test.dart` |
| 4–20 мА | 4/12/20 мА, обратная функция, экстраполяция, нулевой/обратный диапазон | `test/domain_test.dart` |
| НСХ | Pt100 опорные точки, все датчики, границы, монотонность, обратные функции | `test/domain_test.dart` |
| UI | Навигация, поиск, ввод, смена направления, сообщения об ошибках | `test/ui_test.dart` |
| Компоновка | Экран 320 logical px, шрифт 1,5×, светлая/тёмная темы | `test/ui_test.dart` |

Последовательность: `dart format --output=none --set-exit-if-changed lib test`, `flutter analyze`, `flutter test`, `flutter build apk --release`. При дефекте добавить проверку, исправить причину, повторить затронутую группу и общий прогон перед сборкой.

Обратные преобразования подтверждают согласованность функций, но не правильность коэффициентов. Для каждого семейства П/М нужны независимые табличные точки из указанного стандарта.

## Дополнительные сценарии

- Открыть каждый пункт dropdown на узком экране с увеличенным шрифтом, проверить отсутствие переполнения и возможность выбора.
- Раскрыть все разделы справочника, прокрутить до конца, выделить и скопировать текст.
- Проверить поиск по названию, коду, исполнению и номеру руководства, пустой результат и очистку.
- Проверить уникальность `id`, непустую область применимости, уникальные заголовки разделов внутри карточки и HTTPS URL источников.
- Проверить RTD обратное преобразование на границах диапазона преобразователя: численная погрешность не должна давать ложное сообщение «вне диапазона».
- Проверить экранную клавиатуру, поворот устройства, системный шрифт 2× и возвращение из фона.
- Открыть реальный HTTPS источник с браузером, без сети и без подходящего обработчика. Некорректный URI не заменяет тест нативного обработчика.

## Приёмка APK на Android

1. Зафиксировать SHA-256, размер APK, package ID, versionCode, minSdk и подпись.
2. Установить APK на физический телефон; проверить холодный запуск без IDE и USB.
3. В авиарежиме повторить поиск, карточки и все калькуляторы.
4. Проверить темы, системную кнопку «Назад», поворот и возврат из браузера.
5. Выполнить прямой и обратный расчёт каждого семейства НСХ и токового диапазона, сверить с опорными значениями.
6. Проверить обновление APK с прежним ключом подписи и увеличенным versionCode.
7. Записать модель телефона, Android/API и результат каждого сценария. При отсутствии телефона явно отметить, что установка и взаимодействие на устройстве не проверены.

Unit/widget tests не доказывают установку APK, корректность нативного URL-плагина и поведение клавиатуры. Приёмка требует отдельной проверки артефакта на устройстве.
