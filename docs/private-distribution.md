# Закрытое распространение: только владелец

Запрос пользователя от 14.09.2026: приложение должно быть доступно в магазине
только ему. Выбран первый канал — RuStore, бесплатное альфа-тестирование.
Доступ ограничивается магазином, отдельной авторизации внутри приложения нет.
Это ограничение скачивания из магазина, а не защита от пересылки извлечённого APK.

## Постоянная идентичность

- applicationId и namespace: `ru.kiphelper.app`; уникальность проверяется при загрузке.
- Debug-вариант: `ru.kiphelper.app.dev`.
- Первая сборка для магазина: 1.2.1 (4).
- Ключ: `.private/kip-helper-release.jks`, alias `kip-helper-release`, RSA 3072.
- Пароли: `android/key.properties`. Эти файлы не входят в Git и дистрибутив.
- Публичный сертификат: `release-certificate.pem`.
- SHA-256 сертификата: `10bb36a1b9b994a859b45517623666d6323e997e2e1c73cb273e9a1939b8cd7c`.
- Release без настройки подписи останавливается; debug-подпись не подставляется.

Обязательно сохранить защищённую резервную копию keystore и key.properties
вне папки проекта. Агент создал рабочий ключ, но внешнюю резервную копию не делал.
Не отправлять эти файлы в чат, не загружать их вместе с APK. Потеря постоянного
ключа осложняет выпуск совместимых обновлений. Инициализатор
`scripts/init-release-signing.py` отказывается перезаписывать существующий ключ.

Старое тестовое приложение `com.example.kip_helper` остаётся отдельным приложением.
Не удалять его автоматически. Последующие версии `ru.kiphelper.app` подписывать
тем же ключом и увеличивать build number в pubspec.yaml.

## RuStore: конфигурация доступа

1. Создать карточку «КИП Помощник» в консоли разработчика.
2. Открыть «Тестирование → Альфа-тестирование → Альфа-версии» и загрузить APK.
3. Заполнить сведения по `store-listing.md`, использовать медиа из `dist/rustore/`.
4. В «Тестировщики» добавить только свой VK ID, совпадающий с аккаунтом RuStore
   на телефоне. Убедиться, что в списке ровно один нужный пользователь.
5. Отправлять на модерацию именно альфа-версию. Публичный выпуск и бета-канал
   не включать. После модерации открыть тестовую ссылку на телефоне.
6. Для проверки ограничения убедиться, что другой, не включённый в список
   аккаунт не получает альфа-версию. Такая проверка пока не выполнена.

Альфа может быть первой версией приложения. Она доступна через мобильный RuStore;
веб-ссылка первой альфа-версии может возвращать 404. Бета-канал допускает желающих
из каталога и не соответствует требованию «только я».

Официальные источники, проверены 14.09.2026:
- https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/testing/alpha-testing
- https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/testing/beta-testing
- https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication

## Google Play позже

Использовать Internal testing с единственным адресом Google-аккаунта владельца,
без production/open testing. Требование 12 тестировщиков/14 дней касается доступа
нового личного аккаунта к production, а не необходимости добавлять посторонних
во внутренний тест. При настройке Play App Signing согласовать ключ подписи
с RuStore заранее; ключ загрузки AAB и ключ подписи устанавливаемого APK — разные роли.
https://support.google.com/googleplay/android-developer/answer/9845334

## Что ещё не выполнено

Факт входа пользователя в консоль подтверждён им. Автоматизация браузера не запускается:
`failed to write kernel assets` сохраняется после сброса. Агент не создавал карточку,
не загружал APK, не добавлял тестировщика и не отправлял версию на модерацию.
Публикацию нельзя считать завершённой до подтверждения этих действий в консоли.
