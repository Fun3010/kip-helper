Проверки запускать последовательно из настоящей папки без кириллицы; параллельные
Flutter widget-прогоны в одной рабочей копии конфликтуют в `build/unit_test_assets`.
Последовательность: `flutter pub get`,
`dart format --output=none --set-exit-if-changed lib test integration_test`,
`flutter analyze`, `flutter test`. При дефекте добавить осмысленную проверку,
исправить причину, повторить затронутую группу и общий прогон перед сборкой.
`flutter build windows --release --target lib/main.dart` и
`flutter build apk --debug --target lib/main.dart` собирают обычное приложение;
APK integration-теста не подменяет выдаваемую сборку.
`flutter build apk --release --target lib/main.dart` выполнять после
восстановления исходного ключа и проверки его сертификата. Guard подписи не обходить.

## Приёмка Windows x64

1. Проверить commit, версию EXE, состав Flutter/data/PDFium/плагинов/VC Runtime,
   SHA-256 архива и пофайловый манифест. Распаковать весь комплект в новую папку.
2. Запустить `kip_helper.exe` из комплекта; проверить каталог, расчёты, две темы,
   системный выбор PDF, просмотр/поиск и сохранность библиотеки/заметки после перезапуска.
3. Мышью и клавиатурой проверить Tab, активацию увеличения/сброса схемы, возврат,
   доступность полей и крупных подписей при увеличенном системном тексте.
4. Для грязной заметки проверить X и Alt+F4: остаться, отбросить и сохранить/выйти.
   Отдельно отказ/незавершённая запись должны оставлять видимый текст и блокировать
   выход. Программный callback и mock-хранилище не заменяют полный нативный сценарий.
5. Записать версию Windows и проверить комплект на ноутбуке/целевой системе.
   Старт/WM_CLOSE на текущем Windows 10 не доказывает переносимость на другую систему.

## Приёмка APK на Android

1. Зафиксировать SHA-256, размер APK, package ID, versionCode, minSdk и подпись.
2. Установить APK на физический телефон; проверить холодный запуск без IDE и USB.
3. В авиарежиме повторить поиск, карточки и все калькуляторы.
4. Проверить темы, системную кнопку «Назад», поворот и возврат из браузера.
5. Выполнить прямой и обратный расчёт каждого семейства НСХ и токового диапазона, сверить с опорными значениями. Проверить таблицу НСХ, заметки, системный выбор PDF, страницы/поиск и сохранность после полного перезапуска.
6. Проверить обновление APK с прежним ключом подписи и увеличенным versionCode.
7. Записать модель телефона, Android/API и результат каждого сценария. При отсутствии телефона явно отметить, что установка и взаимодействие на устройстве не проверены.

Unit/widget tests не доказывают установку APK, корректность нативного URL-плагина и поведение клавиатуры. Приёмка требует отдельной проверки артефакта на устройстве.
