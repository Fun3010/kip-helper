Оригинальная зашифрованная резервная копия от 02.10.2026 сохранена без изменений:

- [Та же зашифрованная копия в Google Drive](https://drive.google.com/file/d/1hIpNO35zox44wa-uUuUI8kPdTaYBSemc/view?usp=drivesdk).
- Имя: `kip-helper-signing-encrypted-2026-10-02.zip`.
- Размер: **3708 байт**.
- SHA-256: `c991b0986cc79cfecf53cfc886d4efd3529dd11bd00b78bcbf14359c48c375ad`.

При переносе 03.11.2026 архив скачан из Notion и повторно скачан после загрузки
в Drive: размер и SHA-256 обеих копий совпали с исходной записью. Архив не
расшифровывался, его содержимое при этом переносе не проверялось.

По записи Notion внутри находятся `.private/kip-helper-release.jks`,
`android/key.properties` и `RESTORE.txt`. Для распаковки требуется прежний пароль.
Исторический локальный путь пароля — `.private/notion-signing-backup-password.txt`;
сейчас этот файл в рабочем проекте не найден. Наличие ZIP не доказывает возможность
восстановить ключ без пароля.

На новом компьютере сохраните ZIP в `.private/`, проверьте размер и контрольную
сумму, затем восстановите исходный ключ с помощью владельца и программы,
поддерживающей ZIP AES-256. Секреты должны остаться вне Git: `.private/`,
`android/key.properties`, `*.jks`, `*.keystore` уже исключены. Пароль храните
в отдельном защищённом хранилище. Не заменяйте исходный ключ новым для обновлений
приложения. Без восстановленного исходного ключа можно продолжать разработку
и собирать debug APK; совместимую подписанную release-сборку считать готовой нельзя.

## Возобновление на ноутбуке

1. Войти в GitHub, Notion и Google Drive под аккаунтами владельца. Проверить
   открытие трёх ссылок из таблицы.
2. Установить Git, Flutter **3.41.6** / Dart **3.11.4**, Android SDK и JDK **21**.
   Используйте короткие ASCII-пути для проекта и инструментов, например
   `C:\dev\kip-helper`, `C:\tools\flutter`, `C:\Android\Sdk`. Не помещайте рабочую
   копию внутрь папки автоматической синхронизации Drive/OneDrive.
3. Продолжать ветку `release/final-apk-2026-11-03`. На момент подготовки этой
   инструкции её отправка на GitHub ещё не подтверждена. После подтверждения
   отправки выполните в PowerShell:

   ```powershell
   New-Item -ItemType Directory -Path C:\dev -Force | Out-Null
   git clone --branch release/final-apk-2026-11-03 https://github.com/Fun3010/kip-helper.git C:\dev\kip-helper
   Set-Location C:\dev\kip-helper
   git status --short --branch
   git log -1 --oneline
   flutter --version
   flutter doctor -v
   flutter pub get
   flutter analyze
   flutter test
   flutter build apk --debug
   ```

   Если репозиторий уже склонирован: сначала сохранить свои изменения отдельным
   коммитом, затем `git fetch origin` и переключиться на указанную ветку. Не
   сбрасывать чужие или незавершённые изменения. Если ветка ещё не доступна на
   сервере, не подменять её старым архивом без явного решения владельца.
4. Прочитать `docs/superpowers/specs/2026-10-13-project-completion-design.md`,
   `docs/superpowers/plans/2026-10-13-project-completion.md` и актуальную запись
   состояния работ в Notion. Ветка содержит изменения после исторического
   baseline-тега `v1.2.1+4-baseline`.
5. Восстановить внешние материалы и исходный ключ по разделам выше. SDK-пути
   (`android/local.properties`) настроить для ноутбука, не копировать со старого
   компьютера и не добавлять в Git.
6. Перед переходом на другой компьютер отправлять законченные коммиты в Git,
   фиксировать в Notion фактический результат проверок и сохранять новые крупные
   исходники в Drive. APK и архивы должны иметь дату, версию и SHA-256.

Эта инструкция описывает проверенный доступ к хранилищам и восстановление среды.
Установка APK и работа приложения на реальном Android в рамках переноса
хранилищ не проверялись.
